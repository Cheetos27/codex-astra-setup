# Codex Limit Guard

Сохраняй незавершённую работу до исчерпания лимита. Пороги относятся к **оставшемуся**, а не использованному проценту пятичасового окна. Это проверка между действиями, не технический ограничитель расхода: длинный ответ или параллельные задачи могут перескочить порог.

## Проверка

Отличай новый запрос пользователя от пробуждения автоматизации. Для нового поручения в той же задаче создай новое состояние `running` с новым `work_id` и его целью, сохранив прежний checkpoint отдельно при необходимости. Пробуждение никогда не создаёт новое поручение и не сбрасывает `cancelled`, `completed`, `paused_user` или `waiting_user`. Привяжи промпт heartbeat к `thread_id`, `work_id` и `pause_generation` — уникальному идентификатору конкретной остановки. Устаревшее пробуждение не должно продолжать другое поручение или отключать его автоматизацию.

Используй `get_usage_limits` из доступных инструментов Codex. Проверяй в начале работы над задачей; затем на безопасных границах примерно раз в 10 минут при остатке выше 5%. При остатке от 1% до 5% проверяй перед каждым существенным действием. Не запускай отдельный постоянный опрос для обычной работы. Непрерывное рассуждение нельзя прервать такой проверкой.

Не используй периодический модельный heartbeat для наблюдения за квотой. Он пытается запустить модель до выполнения проверки лимитов; инструкция внутри промпта не предотвращает такие попытки при исчерпанной квоте. Если остались созданные этим навыком автоматизации наблюдения, приостанови их штатным инструментом, проверив принадлежность. Проверяй лимиты внутри уже выполняющейся работы. Не создавай фонового субагента для постоянного опроса.

Предпочитай `rateLimitsByLimitId`, выбери подтверждённую корзину текущей модели. Для обычной корзины это `codex`; не смешивай её с отдельными корзинами моделей. Выбирай окно по `windowDurationMins == 300`, независимо от имени primary/secondary. `usedPercent` — расход; остаток равен `100 - usedPercent`. Отсутствующие значения не равны нулю. При неоднозначности корзины сообщи об ограничении вместо выдуманной оценки.

Для проверки порогов используй [scripts/evaluate_limits.py](scripts/evaluate_limits.py). Он принимает JSON тела результата инструмента и локальное состояние, возвращает решение без изменения файлов, сети и запуска модели:

```text
python scripts/evaluate_limits.py --usage usage.json --state state.json
```

Сохраняй только нужные поля результата лимитов, без accountId, credits, токенов или всей истории. Пример минимального входа находится в [references/protocol.md](references/protocol.md). Если инструмент не ответил, сделай одну направленную перепроверку; затем сохраняй прогресс и явно обозначь отсутствие контроля. Уже приостановленную работу без свежих данных не возобновляй.

## Остаток выше 5%

Продолжай согласованную работу. Не создавай активную автоматизацию для завершённой задачи или задачи, ожидающей решения пользователя. Не меняй выбранную модель, reasoning effort или тариф.

## Остаток от 1% до 5% включительно

Сначала сохрани checkpoint по [references/protocol.md](references/protocol.md). Сообщи кратко о низком остатке один раз на окно. Подготовь heartbeat для текущей задачи через `automation_update` в статусе **PAUSED**: он понадобится для продолжения после остановки. Найди существующий экземпляр перед созданием; не дублируй его. Пока работа идёт, автоматизация возобновления не должна быть ACTIVE.

Продолжай только небольшими завершёнными шагами, обновляя checkpoint после каждого. Не начинай дорогую операцию, если остатка может не хватить для сохранения. В этом случае допустимо остановиться раньше 1%, назвав это превентивной остановкой, а не измеренным достижением порога.

## Остаток 1% и ниже

Прекрати запуск новых рабочих действий. Доведи уже начатую атомарную запись до безопасного состояния; не обрывай произвольные процессы и не откатывай чужие изменения. Зафиксируй оставшиеся фоновые операции и их идентификаторы. При делегированной работе попроси только своих рабочих агентов сохранить состояние и остановиться; глобальное правило не даёт полномочий управлять чужими задачами.

Обнови checkpoint, создай новый `pause_generation`, поставь `status: paused_limit`, сохрани наблюдённые `usedPercent` и `resetsAt`. После успешной записи состояния разрешено активировать соответствующий heartbeat только с проверенным первым запуском после ожидаемого сброса всех известных блокирующих окон с небольшим запасом, включив в промпт те же три идентификатора. Обычный повторяющийся интервал без проверенного первого запуска не подходит. Если инструмент не позволяет задать или подтвердить такое расписание, оставь его PAUSED и сообщи, что автоматическое продолжение не настроено. Не заменяй эту проверку обещанием в промпте «жди сброса».

Заверши текущий ход коротким сообщением: что сохранено, когда следующая проверка и зарегистрирована ли автоматизация. Не держи модель в цикле sleep до сброса. Не объявляй исходную задачу выполненной. Для активного goal используй его штатные ограничения; этот навык не разрешает создавать goal или менять его статус вопреки правилам среды.

## Пробуждение

1. Прочитай checkpoint и новые сообщения в этой же задаче. Проверь совпадение `thread_id`, `work_id`, `pause_generation` из промпта с состоянием. При несовпадении закончи без рабочих действий и без изменения автоматизации: она уже может принадлежать новому поручению. Отмена, ручная пауза, завершение и ожидание пользователя имеют приоритет; не продолжай работу. Отключать heartbeat можно только после подтверждения, что его текущее назначение всё ещё совпадает с этим остановленным поручением.
2. Получи свежие лимиты. Продолжай только если остаток пятичасового окна **выше 5%**, есть свидетельство восстановления относительно остановки и нет другого подтверждённого блокирующего лимита. Время сброса само по себе ничего не доказывает.
3. При неизвестных данных оставь задачу на паузе. При ещё низком остатке перенеси следующую проверку к актуальному сбросу. Не создавай частый цикл, расходующий последнюю квоту.
4. Возобновляй исключительно из `paused_limit`. Для проверки callback передай evaluator режим heartbeat и все три ожидаемых идентификатора из промпта; `ignore`, `unknown` и `inactive` не разрешают рабочие действия. Повторно проверь состояние перед записью, затем поставь `status: running` и приостанови принадлежащий этой остановке heartbeat, чтобы не создавать повторные пробуждения. При ошибке приостановки не начинай работу: восстанови паузу и сообщи сбой. Проверь рабочий каталог, ветку, изменения и результаты фоновых операций. Выполняй следующий незавершённый шаг из checkpoint в прежних границах поручения.

После завершения работы установи `status: completed` и отключи только свою автоматизацию. Не возобновляй старую работу вслед за новым несвязанным запросом. Не расходуй reset credits и не покупай квоту.

## Применение во всех задачах

Автоматический выбор навыка сам по себе не является глобальным монитором. Для режима во всех задачах нужна явная инструкция пользователя в личном AGENTS.md: проверять лимиты и применять этот навык. Каждая задача ведёт собственный checkpoint и собственное возобновление. Уже выполняющийся ход может не перечитать изменённые инструкции; не обещай немедленный контроль всех открытых задач.

Навык не устанавливает Windows-службу или hooks. Для работы с локальными файлами при пробуждении компьютер должен быть включён, Codex запущен и рабочий каталог доступен. После исчерпания квоты сам вызов модели по расписанию также может быть недоступен. Различай проверку сценариев, регистрацию расписания и наблюдавшееся реальное возобновление после сброса.
