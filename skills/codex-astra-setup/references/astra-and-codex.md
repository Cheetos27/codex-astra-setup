## Краткие выводы об Astra

Руководство рекомендует явно задавать самостоятельность, стиль, правила делегирования и соразмерность проверки. Astra чувствительна к инструкциям в навыках и AGENTS.md, поэтому конфликтующие требования нужно разбирать.

При миграции с `none` или `minimal` исходной точкой служит `low`; иначе рекомендуется сохранить действующий уровень и сравнить результат. Карточка модели перечисляет `low`, `medium`, `high`, `xhigh`, `max`. Каталог клиента может отличаться.

API и Codex проверяются отдельно. В API для работы инструментов Astra требуется Responses; `temperature`, `top_p` и ряд полей logprobs не поддерживаются. Async tools, steering и `configuration_update` требуют реализации в вызывающей программе. Они не являются готовыми переключателями config.toml. Подробности и ограничения сверяй по текущему руководству только при соответствующей API-задаче.

## Применение в Codex

В проверенной версии пользовательские настройки находятся в `$CODEX_HOME/config.toml` (обычно `~/.codex/config.toml`), а отдельный профиль — в `<имя>.config.toml` рядом с ним. Проектные и явные настройки могут переопределять личные. Проверяй текущую схему и справку клиента.

Минимальный пример **дополнительного профиля**, если клиент подтверждает поддержку:

```toml
model = "gpt-6-astra"
model_reasoning_effort = "medium"
```

Имя вроде `astra-balanced` — условность данного проекта. В качестве вариантов можно предложить `astra-quick`/`low`, `astra-balanced`/`medium`, `astra-deep`/`xhigh`, `astra-max`/`max`. Не создавай все автоматически, если они не нужны. Для одного режима достаточно личного конфига. Более высокий уровень не гарантирует более полезный ответ.

## Наблюдения из исходной настройки

Это опыт одной Windows-среды, а не факты обо всех установках:

- Рабочий `high` уже был задан. Его сохранили; краткость и актуальный веб-поиск тоже были настроены.
- У Python искажалась кириллица. Переменные PYTHONUTF8 и PYTHONIOENCODING исправили отдельную проверку дочернего процесса. На другом компьютере сначала воспроизведи проблему.
- В диагностике сетевой тайм-аут сменился успешным WebSocket-подключением. Это не доказывает постоянную неисправность конфигурации.
- `--profile` не поддерживался у `doctor`, а `--strict-config` — у `features`. Основной конфиг проверили через `codex --strict-config doctor --json`, профили — через `codex --profile ИМЯ mcp list`. Эти команды снова проверь через справку перед использованием.
- Изменения в личных файлах не доказывают, что уже работающая задача загрузила их. Не смешивай сохранённое значение и фактические параметры текущей сессии.
