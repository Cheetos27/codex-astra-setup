# Совместное использование с Z.A.E.B.A.L.

Дополнительный навык автора [howdeploy](https://github.com/howdeploy/Z.A.E.B.A.L) предназначен для разбора повторяющихся ошибок агента. Имя навыка — `zaebal`, название проекта — **Z.A.E.B.A.L.** Проверенная для этой интеграции версия: `ea5e18fb2c5b8ec700fb4ad36bad5f91bd8c269d`, 18 сентября 2026 года.

## Что подключается

Исходный [SKILL.md](https://github.com/howdeploy/Z.A.E.B.A.L/blob/ea5e18fb2c5b8ec700fb4ad36bad5f91bd8c269d/skills/zaebal/SKILL.md) описывает аудит истории задачи, сопоставление предположений с результатами и независимую проверку. Его условия применения включают направленное на агента недовольство с руганью; обсуждение самого навыка не запускает аудит. Протокол предусматривает внутренних аудиторов, а старшие уровни — остановку до подтверждения пользователя.

Отдельный автоматический hook анализирует сообщения и ведёт состояние инцидентов. Он может запускать внешний CLI-аудитор с контекстом разговора. Копирование папки навыка этот runtime не устанавливает и hook не регистрирует.

## Установка по поручению пользователя

1. Определи целевую среду. Эта интеграция относится к Codex; установка локальной папки не означает установку в аккаунт на chatgpt.com.
2. Проверь, установлен ли `zaebal`. При наличии сохрани его версию и пользовательские изменения; не заменяй их без необходимости.
3. Прочитай исходный навык выбранной версии. Для воспроизводимой установки используй указанный commit; для обновления сначала проверь изменения upstream.
4. Используй доступный Skill Installer с репозиторием `howdeploy/Z.A.E.B.A.L`, путём `skills/zaebal` и выбранным `ref`. Если установщика нет, следуй инструкции репозитория для установки только навыка. Не запускай общий shell-установщик на Windows по предположению.
5. Сверь установленные файлы с выбранным источником и проверь формат навыка. Отдельно сообщи, когда клиент сможет его обнаружить. Успешное копирование не доказывает активацию hook или качество будущего аудита.

Пример поручения после установки:

```text
Используй $zaebal. Разбери, почему мы повторяем одну ошибку в этой задаче.
```

## Границы связки

- `codex-astra-setup` отвечает за настройку среды. Для аудита используй установленный `zaebal`, предварительно прочитав его текущие инструкции. Не загружай весь протокол в каждый обычный запрос и не копируй его в глобальный AGENTS.md.
- Сохраняй условия автоматического выбора исходного навыка. Выбор моделью подходящего навыка не равнозначен гарантированному срабатыванию hook на каждое сообщение. Не выдумывай счётчик инцидентов и внешний вердикт при отсутствии runtime.
- При выполнении аудита учитывай разрешения текущей среды на субагентов. Если независимые проверки недоступны, явно укажи ограничение. Не выдавай собственную проверку за независимую.
- Общая предпочтительная автономность не отменяет явно выбранный режим аудита. Если его протокол требует паузы, укажи конкретный пункт установленного SKILL.md и объясни, какое решение нужно от пользователя; не вводи такую паузу за пределами этого режима.
- Автоматический hook настраивай только при соответствующем поручении. Прочитай инструкцию для ОС целевого процесса, проверь выбранного внешнего аудитора и объём передаваемого контекста. Сохрани существующие hooks и резервную копию. Различай отдельную проверку скрипта и подтверждённую загрузку hook самим Codex.

## Авторство и распространение

В проверенной версии upstream отдельный файл лицензии не обнаружен. Поэтому наш пакет содержит собственную инструкцию подключения и ссылки; исходные файлы Z.A.E.B.A.L. в него не включены. MIT нашего репозитория не распространяется на проект howdeploy. Перед включением чужих файлов в распространяемый пакет проверь условия автора.
